Backend
- Keep Django apps as-is; optionally introduce backend/api/ to group unified REST endpoints and shared API concerns (pagination, permissions, throttling). Update root urls.py to include api.urls.

Rationale
- Feature-first structure clusters data/domain/presentation per feature, improving modularity and scalability (common in large Flutter apps and similar to Uber/Bolt patterns).
- Core shared layer centralizes cross-cutting concerns (routing, services, widgets, design tokens) for consistency and reuse.
- Clear ownership boundaries simplify navigation shell management and reduce duplication (e.g., Account settings integrated within Account feature).
